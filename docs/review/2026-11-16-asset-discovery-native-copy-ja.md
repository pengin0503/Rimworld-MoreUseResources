# 2026-11-16 コードレビュー：アセット探索とRAMコピー鮮度

対象: PR #2 / `feature/content-audit-20261116`（RimWorld 1.7向け）

## 確認範囲
- `ResourceController`: アセット探索を起動する条件・CPU/RAMフェーズ・ソース一覧更新・停止/メモリガード
- `GameAssetFiles`: 有効MODフォルダ下の既知ディレクトリと拡張子のみを検出する制限
- `FileCache`: 初期OS先読み、定期再先読み、ネイティブRAMコピー、メモリ解放とクールダウン
- `NativeBlockStore`: pending/committedの所有権、解放通知、アセット単位の解放
- `AssetAudit`, `XmlManifestScanner`, `TextureAssetInspector`: 監査の再走査・読み取り専用制限・不正データの扱い
- `TexturePrewarm`: Waylith限定のメインスレッド先読み、VRAM予算、保留キュー、サイズ制約

## 確認した問題と修正

### Issue #3 — 一度しかアセットを列挙しない
根本原因: `ResourceController.QueueAssetScan` の成功状態が2で固定され、状態0だけを許すCASでは再実行できなかった。

変更:
- `AssetDiscoveryRescanMinutes`（既定10分、0でOFF、上限120分）を追加。
- 成功状態2からも設定間隔経過後に、低優先度ワーカーで実アセット一覧を再取得。
- 同時探索は1つに制限。既存のアセット列挙上限、フェーズ/メモリ/停止の制御を維持。
- 一覧の**集合が等価**なら、`FileCache` と `AssetAudit` の状態をリセットせず、RAMコピーを保護。
- 新規/削除ファイルを含む一覧変更時のみ両機能を更新。完了回数と一覧変更回数を表示。
- 回帰テスト: 初回・同じ一覧・追加・削除、疑似時計による再探索間隔。

### Issue #4 — 保持済みファイルコピーの鮮度が更新されない
根本原因: `_done` で所有済みRAMコピーの再読み込みを抑止し、OS再先読み時はファイルを読み捨てるのみでコピー内容の変化を照合していなかった。

変更:
- コピー作成時に実ファイルのSHA-256をチャンク単位で計算し、所有中のパス別に記録。
- OS再先読み時、保持済みコピーがある場合だけ実ファイルのSHA-256を再計算し、内容を照合。
- 不一致のとき、`NativeBlockStore.ReleaseKey` で**該当ファイルだけを解放**。他アセットのコピーは維持。
- 既存の30秒クールダウン後に更新ファイルを再読込。RAM予算と割り当て中のpendingブロックの保護を維持。
- `FileCache.Reset` がコピーを残したまま同一ファイルを二重確保する状態も修正。
- 回帰テスト: 同サイズ内容更新、異サイズ更新、別アセットの保持、Reset時の重複防止、ファイル別解放通知。

## 残る境界・実機検証条件
- このMODがRAMに私有保持するファイルコピーは**RimWorld本体のローダーに接続されていない**。CPU/RAM使用率を増やしOSのファイルキャッシュを温める効果が中心であり、FPS/TPS/ロード時間短縮は未実証。
- アセット再探索は定期方式で、MODを動作中に有効化したり読み込み順を変える仕組みではない。対象は既存の有効MODロードフォルダのみ。
- GPU先読みはWindows版RimWorld 1.7.5011 rev24 / Waylith限定。GPU実機のVRAM圧迫、フレーム時間、描画やテクスチャ復元動作は別途検証。
- WOWGAG/Overclock/Axenとの同時動作をゲーム内で確認していない。これらのパッチは複製していない。
- セーブ/オートセーブ・一時停止・ウィンドウ非アクティブ・メモリ圧迫時の安全ガードは保持する。実ゲームのログでの検証は必要。
