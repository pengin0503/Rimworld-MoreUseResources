# 既存のバニラ処理にリソースを使う実装計画

対象はWindows版RimWorld 1.7.5011 rev24、.NET 10、Waylith。[併用計画](2026-11-17-performance-mod-resource-coexistence-ja.md)のタスク5を具体化する。

**目的**

ゲーム本体が実行するロード、テクスチャ展開・圧縮、描画資源の準備、JIT・GCにCPU・RAM・GPU・VRAMを使う。既存のワーカー、OSキャッシュ、ゲームのテクスチャキャッシュとドライバー予算を利用する。追加の機能は、既存処理を先に進める、待ち時間を減らす、キャッシュを維持する、または本体既存の処理方式を選択するためのものに限定する。

WOWGAG・Axen・Overclockに同じ処理のパッチがある場合は、[併用設計](../specs/2026-11-17-performance-mod-resource-coexistence-ja.md)の優先判定に従う。公式コンテンツに加え、バニラの同じローダー・描画経路で読み込まれる有効MODの素材も対象とする。

## 対象と担当

| 本体の既存処理 | リソースの使い方 | MoreUseResourcesの担当 |
| --- | --- | --- |
| テクスチャ・音声・Defsなどをバニラローダーが読む | CPUワーカーで既存ファイルを先に読み、OSのファイルキャッシュに載せる。公式パックは既存の常駐設定を適用できる | 併用計画タスク3のコピー予算不足時のOS先読みを完了する。先読み候補、キャッシュ、同時起動時のI/O予算を共有する |
| Waylithがテクスチャを展開・圧縮し、必要になった画像をGPUへ載せる | ゲームが使うテクスチャの再アップロードを既存の先読み処理で先行する。初回の圧縮に本体のGPU経路を選べる | タスク4の需要履歴を実装する。圧縮は既存ランチャーの `-GpuTextureEncoding` を使う。アトラス除外、VRAM予算、メインスレッド側の処理上限を維持する |
| 本体の描画用グラフィック・マテリアルが初回利用時に準備される | 既存のゲームキャッシュへ先行して構築する | PR #5の `GpuPrepareGraphics` で対応している経路を使う。対象拡張には、通常の描画側が同じキャッシュを参照することを静的に照合する |
| ゲーム本体・MODの管理メソッドがJITコンパイルされ、ランタイムがGCする | 既存のJIT事前準備やランチャーのServer GC設定にCPU・RAMを使う | 既存設定を使い、WOWGAGとの重複は併用計画タスク1・2の優先処理に従う |
| バニラがユーザーの選択したセーブを読み込む | 指定した `.rws` のデータを先にOSキャッシュへ載せる | 下記の読み取り準備を追加する。実際のロードは通常のセーブ選択とゲーム内ローダーが行う |

## 追加作業　選んだセーブの起動前先読み

- [ ] `tools/Start-RimWorldGc.ps1` に明示の `-WarmSaveFile` を追加する。既存ランチャーのパック先読みと同じ読み取り方式を再利用し、指定された1本の `.rws` だけを読み取り専用で処理する。ゲーム起動後は通常どおりそのファイルをロード画面で選ぶ。
- [ ] セーブ分の初期上限は256 MiB・5秒とし、パック先読みと併用した場合も、既存の起動前の容量・時間予算を合計で守る。同じセーブを明示指定した場合は、共有予算の中で先に処理する。空きRAMの下限は既存設定の考え方に合わせ、取得不能時や読み取り失敗時も通常起動へ進める。
- [ ] PowerShellの構文と、一時ファイルを使った対象選択・容量上限・中断・読み取り失敗を確認する。先読みした量と所要時間を出し、READMEに指定方法を記載する。

Waylith本体にはテクスチャと音声を読む並列先読みがある。公開逆コンパイル資料ではワーカー上限と保持量が内部定義で、`Enqueue` と `Drain` はスロットを共有する。追加のOS先読みはそのキューの中身や上限に介入せず、同じ実ファイルを通常のローダーから利用できるようにする。[Waylithの既存先読み](https://github.com/codexvn/RimWorldDecompiled/blob/d5cbe1186bbb9962b7bd4913c900441c6fe4a4ff/Waylith/Waylith.Rendering/AssetPrefetcher.cs#L65-L155)

## 完了条件

成立する経路は、速度向上や有用性の実測結果を待たずに実装する。単体テスト、静的なAPI照合、Releaseビルド、同梱DLL・配布物確認で完了とする。実ゲームの起動・プレイ・性能測定は、この実装工程に含めない。
