# Rimworld-MoreUseResources

RimWorld 1.7で、CPUワーカー・RAM・VRAMを動作フェーズごとに使うMODです。基準は **Windows 1.7.5011 rev24 / .NET 10 / Waylith** です。1.7.5014 rev1195 にも対応します（下の「ビルドと検証」）。

## 導入

1. RimWorld 1.7対応の **Harmony 3** を導入し、本MODの前にロードします。
2. ZIPを解凍し、`Rimworld-MoreUseResources` フォルダをゲームの `Mods` に配置します。中に `About/About.xml` と `Assemblies/MoreUseResources.dll` があれば正しい構成です。GitHubのソースZIPを展開して使う場合も同じ構成です。
3. MODを有効にして再起動し、**オプション → MOD設定 → More Use Resources** を開きます。設定画面は日本語・英語に対応します。

## 動作と設定

| リソース | 実行する処理 | 初期値 |
| --- | --- | --- |
| CPU | ワーカーで有効なMODと公式コンテンツのアセットを読み、OSのファイルキャッシュへ先読みします。さらに実アセットのSHA-256索引化と完全一致重複の検出をCPU単独で実行できます。ワーカー上限と実験的なCPU負荷生成の稼働率を設定できます。 | 最大4ワーカー、アセット索引ON、CPU負荷生成OFF |
| RAM | ゲームが実際に読むテクスチャキャッシュZIP・Assets.zipとMODアセットをOSファイルキャッシュに先読みし、初回の読み取り後も設定間隔で再先読みします。Assets.zipのRAM常駐、ファイルコピーの保持、追加予約は個別設定でき、OSの空き容量を監視します。 | OS先読みON・再先読み5分間隔、プロセス内コピーON、Assets.zip常駐・追加予約OFF、使用可能RAMの下限6 GiB |
| GPU | Waylith経由で、未常駐かつ再読込可能な小型テクスチャを先読みします。ドライバー予算に対する上限、残す容量、処理時間の目安を設定できます。 | 実験機能OFF |

- CPU・RAMは起動後、タイトル画面、ロード・マップ生成、通常速度、高速、ゲームのポーズ、セーブ・オートセーブで個別に切り替えられます。高速は通常より上のゲーム速度です。初期状態ではセーブ中に新規作業を抑え、ウィンドウが非アクティブな間は休止します。
- CPU設定は並列ワーカーと追加負荷に適用します。RAM設定だけでファイルコピーを有効にした場合も、読み取り用のワーカーを1つ使います。RAMの実行枠がOFFのときは、CPUワーカーがOS先読みだけを行います。
- **OSファイルキャッシュ再先読み**では、初回の読み取り完了後に設定した間隔（初期5分、0で無効、最大120分）で有効MODの実アセットを再読込します。一度読み込んだファイルも対象となるため、OSが破棄したファイルキャッシュの再形成を試みられます。RAMコピーを保持しているファイルは初回読取時のSHA-256と再先読み時のSHA-256を比較します。**内容が変わった場合のみ古いRAMコピーを個別に解放**し、既存の30秒クールダウン後に実ファイルを読み直します。同じファイルの二重確保を避け、変わっていないコピーは保持します。ゲームはこれらの私有コピーを参照せず、OSのファイルキャッシュを利用します。失敗・停止・メモリ不足・予約解放後の再試行には既存の安全ガードとクールダウンを適用します。SSDからの実読み込み量が増える場合があり、FPS/TPS改善は未検証です。
- 「今すぐ実行」は手動で強度100%にします。セーブ、非アクティブ時、ワールド画面の設定、メモリ予算は引き続き適用されます。「RAM解放」はMODが保持するコピーと予約を解放して一時停止します。「自動」でフェーズ制御に戻ります。
- 状態欄にフェーズ、ワーカー枠、CPUワーカーが使用する全論理CPU比率、FPS・TPS、フレーム間隔（約1秒間隔で更新）、**OSファイルキャッシュ再先読み完了回数**、アセット検査の進捗・再検査回数・変更検出数、コピー・予約した容量、プロセスのワーキングセット、GPUの最終予算サンプルと保留テクスチャ件数を表示します。FPS・TPSはMOD導入後のゲーム内計測であり、導入前との差分は自動判定しません。
- 状態欄の一番上の **状態をコピー** は、状態欄の全行、ゲームの版、MOD数、論理CPU数、VRAMの使用量と予算、全設定をクリップボードに入れ、同じ内容を `Player.log` にも `[More Use Resources] Status snapshot:` として書きます。状態欄の「この起動中のプレイ」は、ポーズしていない10秒の区間だけを足した、ゲーム速度と速度の倍率ごとの平均です（TPSと目標に対する割合、FPS、GCの回数と停止時間、確保速度、ゲーム全体・メインスレッド・PC全体のCPU使用率、スレッドの種類別のCPU、メインスレッドの時間のうちティック・マップ更新・UIの割合、JIT時間、I/Oの読み取り量、ハードページフォールト、50 ms・100 msを超えたフレーム数、空きRAMの最小値、RAMへ退避されたテクスチャ数、計測自体にかかった時間）。別のウィンドウに切り替えて更新が止まっていた区間は捨てます。「起動からロード完了までの合計」はCPU、メインスレッド、JIT、GC、読み取り量、スレッド別のCPU秒、ハードページフォールト、アセットパックの統計です。コピーには画面サイズ、フレーム上限、エンジン自身のRAM・VRAM内訳レポートと、`DOTNET_`・`COMPlus_`・`WAYLITH_` で始まる環境変数も入ります。追加の処理は、ティック・マップ更新・UIの呼び出しごとに時計を2回読むことと、10秒ごとのスレッドの読み取りだけです。

## 実装範囲

- 先読み対象は有効なMODの `Defs`、`Patches`、`Languages`、`Textures`、`Sounds` 内の対象ファイルです。先読みは読み取り専用です。設定はRimWorldのMOD設定ファイルに保存されます。
- ゲームが再利用できるのはOSのファイルキャッシュです。プロセス内コピー、RAM予約、CPU負荷生成は使用量を増やすための任意機能です。FPS・TPS・ロード時間の改善は計測していません。
- **エンジンのテクスチャキャッシュとアセットパックの先読み**: RimWorld 1.7（Waylith）は、一度変換したテクスチャを `<キャッシュ保存先>/TextureCache/v<番号>/<圧縮設定>/<MODフォルダ名>-<16桁>.zip` に保存し、次回以降の起動ではソースのPNGを開かずにこのZIPから読みます。プレイ中に必要になったテクスチャもメインスレッドがこのZIPから読みます。公式コンテンツは各ロードフォルダとゲーム本体の `Assets.zip` に入っています。本MODは有効MODに対応するこれらのZIPを**ソースファイルより先に**OSファイルキャッシュへ先読みし、定期再先読みの対象にも含めます。キャッシュの使用世代を更新日時だけでは確定できないため、複数世代に同名ZIPがある場合も候補を残し、新しい更新日時のファイルから先読みします。ZIPはプロセス内RAMコピーの対象には含めず、1GiB超でもOS先読みの対象です。読み取り専用で、ZIPの中身は解釈しません。SHA-256索引・XML・テクスチャ検査の対象には含めません。状態欄に対象ZIPの個数を表示します。本体1.7.5011 rev24の逆コンパイルに基づく実装で、実機での効果は未計測です。
- **Assets.zip のRAM常駐（実験機能・初期OFF）**: 各ロードフォルダとゲーム本体の `Assets.zip` を読み取り専用でメモリマップし、ページをRimWorldプロセスのワーキングセットに載せます。エンジン自身が同じファイルを読み取り専用でマップしているため、同じ物理ページを共有します。コピーは作らず、書き込みもしません。上限（初期2048 MiB）を超えるファイルはマップしません。OSの空きRAMが下限を下回ったとき、「RAM解放」を押したとき、機能をOFFにしたとき、「非アクティブ時に解放」の条件を満たしたときにマップを解除します。OSファイルキャッシュ再先読みと同じ間隔でページに触れ直します。エンジンが書き換えるテクスチャキャッシュZIPはマップしません（Windowsではマップ中のファイルを縮小・置換できないため）。タスクマネージャーの「メモリ」には共有分として計上され、プライベート使用量は増えません。FPS・TPS・ロード時間の改善は未計測です。ディスクの読み取りエラーがマップ領域内で起きるとプロセスが異常終了し得るため、各チャンクを通常のファイル読み取りで先に読んでから触れます。
- **ロード工程の計測（初期ON）**: 本MODの生成後に実行される本体のロード工程（`LoadModXML`、`CombineIntoUnifiedXML`、`ErrorCheckPatches`、`ApplyPatches`、`ParseAndProcessXML`、`ResolveAllWantedCrossReferences`、暗黙Def生成、`StaticConstructorOnStartupUtility.CallAll`、`BakeStaticAtlases`）の所要時間を計り、ロード完了時に `[More Use Resources] Load timing: …` としてログへ1行出力し、状態欄にも表示します。プロセス開始から本MOD生成までの時間、本MOD生成からロード完了までの時間、プロセスのピークワーキングセットも記録します。Harmonyのprefixとfinalizerで時刻を読むだけで、元の処理・引数・例外には手を加えません。テクスチャと音声の読み込みは本MODの生成より前に終わるため、個別には計れず「プロセス開始から本MOD生成まで」に含まれます。設定の変更は次回起動から有効です。
- **GCの計測表示**: 状態欄に直近10秒のガベージコレクション回数（世代別）、全スレッドが停止した時間とその割合、マネージドメモリの確保速度、ヒープ量、GCの種類（Workstation／Server）と遅延モードを表示します。比較用の計測値を保存し、起動間で比較できます。
- **CPUアセット索引**は有効MODのDefs、Patches、Languages、Textures、Soundsに含まれる実ファイルのSHA-256を低優先度ワーカーで計算し、完全一致ファイル数と重複容量を集計します。RAM先読みが無効でもCPU単独で実行できます。ゲームデータは変更せず、各ファイルは最大1GiB・最大5万件の走査対象という上限の範囲で検査します。初回完了後は設定間隔（初期10分、0で再検査なし）ごとに実ファイルを再ハッシュし、同じサイズの内容変更も検出します。**ファイル一覧の再探索**も独立した間隔（初期10分、0で無効）で実行し、新規・削除された実アセットを反映します。探索結果に変化がない場合は保持RAMコピーと監査済み結果を維持します。監視は定期間隔であり、リアルタイム通知ではありません。
- **テクスチャ実データ検査**では、低優先度CPUワーカーでMODのPNGのチャンクCRC32・ヘッダー構造とDDSの128バイトヘッダーを読み取り専用で検査し、正常／不正／容量超過の件数、画像寸法、RGBA8非圧縮換算のベースレベル容量を集計します。PNGのIDATデータの実デコードやDDSの圧縮データ検証はしません。RGBA8換算量はゲームGPUドライバーが実際に確保したVRAMの測定値ではありません。1画像最大128MiB、PNGチャンク最大65536個、寸法最大16384pxの制限があります。
- **XMLの実データ解析**は上記のCPUアセット検査中にXMLをもう一度安全にストリーム読込し、各`Defs`直下の実体Def数と、同種Defの同じ`defName`の重複**候補**を数えます。抽象Defは名前照合対象外です。DTDと外部実体を無効化し、1 XMLあたり8MiB、最大深さ64、1ファイルの名前索引8192件、全体索引25万件に制限します。XMLの解析失敗・サイズ超過・上限による省略数も表示します。名前の重複はゲームでの競合を確定するものではありません。XMLアセット検査の結果はゲームXMLローダーと独立しています。
- 添付されたWOWGAG、Overclock、Axenの実行DLLは**本MODへ同梱しません**。それらの最適化や並列Pawn Tickを複製しません。併用時の動作は下の「他のパフォーマンスMODとの併用」を参照してください。詳細は[調査資料](docs/research/2026-11-16-reference-performance-mods-ja.md)を参照してください。
- **コピー予算が足りないファイルのOS先読み**: プロセス内コピーの予算が足りず保留になったファイルも、読み取り条件（フェーズ設定、空きRAMの下限、セーブ中でないこと）を満たしていれば、実ファイルを1回読んでOSファイルキャッシュへ載せます。コピーは予算が空いたときに再試行します。状態欄に件数を表示します。
- **コンパイル済みシェーダーの先読み**: Waylithは `<キャッシュ保存先>/ShaderCache/<SHA-256の64桁>.spv-cache` を通常のファイル読み取りで丸ごと読みます。この名前の形に一致するファイルだけを既存のOS先読み対象に加えます（最大4096件、読み取り専用、RAMコピーの対象外）。起動前の先読み一覧にも最大512件を記録します。
- 区画メッシュのGPU転送の前倒しは実装していません。本体は区画を再生成するたびに `RefreshSubMeshBounds` でメッシュをエンジン用の形式へ変換して転送キューに入れ、エンジンは次のフレームで画面外の区画も含めてキュー全体を転送します。前倒しできる処理が残っていないことを静的に確認しました。
- **画面外区画の先行更新（実験機能・初期OFF）**: ポーズ中に限り、現在のマップで変更フラグが立っている画面外の区画を、本体自身の再生成メソッドで1フレーム1区画ずつ更新します。本体はこの更新を区画が画面に入るフレームまで遅らせています。更新結果とメッシュの転送は本体とエンジンがそのまま使います。
- **テクスチャ需要履歴（需要優先がONのとき）**: Waylithが記録した再読み込み回数の順位を `MoreUseResources-TextureDemand.json`（ユーザーデータフォルダ、最大512件・1 MiB）に保存し、次回起動時に同じ画像から先読みします。キーはMODのパッケージIDとコンテンツ内の相対キーで、絶対パスは保存しません。MOD構成と順序、本体ビルド、キャッシュ世代、パックのサイズと更新日時が一致するときだけ使います。今回見なかった画像は回数を半分にして残します。セーブデータには書き込まず、削除しても動作に影響しません。
- ポートレートの事前準備は実装していません。本体のポートレートキャッシュは最終使用から1秒で期限切れになり、パラメーターが完全一致した場合しか再利用されないため、事前に作っても使われないことを静的に確認しました。
- GPU先読みは **Windows 1.7.5011 rev24 と 1.7.5014 rev1195** の単体GPUで、Waylithのテクスチャ用デバイスローカルヒープとVulkanドライバー予算を識別できる場合に、タイトル・通常速度・高速・ポーズの安定したフレームで動きます。起動・ロード・セーブ中にはGPU処理を開始しません。
- GPU先読み対象の幅・高さ上限は初期1024pxで、設定画面から最大4096pxまで拡張可能です。上限を大きくすると既存のゲームテクスチャのうちより大きな画像もGPUへ先読みされますが、フレーム時間の増加や一時的なVRAM圧迫につながる可能性があります。VRAM予算・最低空き容量・フレームガードは継続して適用します。**初期値のままでは対象画像サイズは増えません**。
- GPU処理は安定フレーム中に最大4テクスチャを段階的に先読みし、成功するたびに実ドライバー予算を更新します。指定時間の目安・フレームガードは維持しますが、単一のアップロードは指定時間を超える場合があります。予算が足りないテクスチャは最大2048件まで一時保留し、後続の小型テクスチャを優先します。**一巡して保留がなくなった後は初期60秒間隔（0でOFF、最大600秒）で再走査**し、Waylithが退避した対象テクスチャの再先読みを試みます。VRAM不足による保留が残る場合は、その処理を優先し新しい一巡を始めません。常駐した画像はWaylithが管理します。VRAMの人工予約、テクスチャの強制退避、GPUの合成負荷は提供していません。
- WindowsのメモリAPIとLinuxの `/proc/meminfo` をサポートします。OSから使用可能メモリを取得できない環境ではRAM追加確保と先読みを停止します。

## 他のパフォーマンスMODとの併用

WOWGAG's Performance Patch、Overclock、Axen's Performance Enhancementsと併用しても、**本MODのワーカー上限と処理量は下げません**。上限を決めるのは本MOD自身のフェーズ設定、ワーカー上限、適応制御、フレームガード、RAM・VRAM予算だけです。Waylithの共有ジョブプールが混んでいることも削減条件にしません。

- **同じ作業だけを譲ります**。他MODが本体の同じメソッドを置き換えている場合（Harmonyのトランスパイラー、または元の処理を飛ばせるprefix）に限り、その作業単位だけを相手に任せます。計測用のprefixやpostfixのように結果を変えないパッチは譲渡の理由にしません。空いた処理枠は、譲っていない残りの作業に回します。
  - WOWGAGのXML再利用が有効、または判定できない場合: `LoadModXML` と `CombineIntoUnifiedXML` の計測、およびXMLパッチキャッシュ。
  - WOWGAGのJIT準備が有効な場合: 本MODのJIT先行コンパイル。
  - グラフィック生成、区画の描画・再生成を置き換えるパッチがある場合: それぞれグラフィック資源の事前構築、画面外区画の先行更新。
  - ファイルのOS先読み、シェーダーキャッシュの先読み、テクスチャ先読み、アセット検査は、他MODが入っているだけでは止めません。
- **状態欄の表示**: WOWGAGの `parWorkers` とOverclockの `parallelThreads` は「設定値（0は自動）」と「現在の稼働数」を分けて表示します。並列機能がON／OFFか、相手自身の判定で止まっているかも表示します。読み取れない場合は「判定不能」「読み取り不可」と表示し、推測値は出しません。
- **Axenの経路探索**: Waylithの共有ジョブプールで動きます。Axenに専用のワーカー設定は作らず、共有プールの設定も変更しません。経路グリッド発行メソッドのHarmonyオーナーと共有プールの状態を診断として表示するだけです。
- **他MODの設定は通常起動では書き換えません**。ゲーム内からも書き換えません。ワーカー数を変える方法は各MODの設定画面です。起動スクリプトで明示的に指定した場合に限り、確認済みの設定値を変更できます（下記）。

### 起動スクリプトで他MODのワーカー数を指定する（任意）

対象MOD、設定ファイル、ワーカー数の**3つをすべて指定したときだけ**、そのファイルのワーカー数を書き換えます。1つでも欠けると何も変更せず警告を出します。

```powershell
.\tools\Start-RimWorldGc.ps1 -GameExecutable "D:\Games\RimWorld\RimWorld.exe" -Profile Default -ExternalWorkerOwner Wowgag -ExternalWorkerCount 8 -ExternalSettingsPath "D:\RimWorldUserData\Config\Mod_3797541313_GppMod17.xml"
```

| 対象 | 設定名・型 | 範囲 | 反映 | 確認元 |
| --- | --- | --- | --- | --- |
| `Wowgag` | `GUIPerformancePatch.GppSettings` の `parWorkers`（整数、初期0＝自動。0のときはファイルに書かれません）。ファイル名は `Mod_<フォルダ名>_GppMod17.xml` | 0〜32 | 起動時。WOWGAGは値が変わるとワーカープールを作り直します | 配布版（Workshop 3797541313、2つのビルド）の1.7用DLLを逆コンパイルして確認 |
| `Overclock` | `Overclock.OverclockSettings` の `parallelThreads`（整数、初期0＝自動。0のときはファイルに書かれません）。ファイル名は `Mod_<フォルダ名>_OverclockMod.xml` | 0〜論理CPU数−1 | 再起動後。ワーカープールは並列Pawn Tickの適用時に1回だけ起動します | 配布版（Workshop 3828406061）の1.7用DLLを逆コンパイルして確認 |

- 変更前に、ルート要素・設定クラス名・ファイル名・値の型と範囲を確認します。一致しない場合、RimWorldが実行中の場合、準備中にファイルが変わった場合は変更しません。
- 変更するのは該当する1つの値だけです。元のファイルは同じフォルダに `<ファイル名>.mur-backup-<日時>` として残します。これは相手MODの設定の恒久的な変更です。戻すにはバックアップを戻すか、相手の設定画面で変更してください。
- 値が初期値の0でファイルに書かれていない場合は、要素を1つ追加します。0を指定した場合は何も変更しません。
- 並列機能のON／OFFと、MOD間の優先関係（WOWGAGはAxenがあると自身の並列処理を止める、OverclockはWOWGAGの並列設定がONだと並列Pawn Tickを適用しない）は各MODの判定に任せ、本MODとスクリプトは変更しません。Overclockの自動値は「論理CPU数が8以上ならその半分、未満ならそのまま」から1を引いた数です。

### 起動前に選んだセーブを先読みする（任意）

```powershell
.\tools\Start-RimWorldGc.ps1 -GameExecutable "D:\Games\RimWorld\RimWorld.exe" -Profile Default -WarmSaveFile "D:\RimWorldUserData\Saves\Colony.rws"
```

指定した `.rws` を1つだけ読み取り専用で読み、OSファイルキャッシュに載せます。セーブは自動では選ばず、ロードはゲームのメニューから行います。`-WarmSaveBudgetMiB`（初期256）、`-WarmSaveTimeoutSeconds`（初期5）、`-WarmMinFreeMiB`（空き物理RAMの下限、初期6144、0で確認なし）で制限します。パック先読みと合計の容量・時間を共有します。読めない場合は先読みを省略してそのまま起動します。`-NoLaunch` を付けると、ゲームを起動せずに準備だけを行います。

## ハードウェア活用の実験設定

追加の実験設定は初期OFFです。テクスチャキャッシュ、XMLキャッシュ、GPU設定はWindows 1.7.5011 rev24 と 1.7.5014 rev1195 が対象です。

| 設定 | 動作と解除方法 |
| --- | --- |
| GCプロファイルと比較 | Windows PowerShellの起動スクリプトからWorkstation／Server GCを指定できます。設定は起動したゲームプロセスに限って適用され、通常の起動方法に戻すと解除されます。状態欄のボタンで同一フェーズの10秒以上の計測窓を保存し、起動間で回数・停止時間の毎分換算、ヒープ量、GCコミット済みメモリ、確保速度を比較します。低遅延モードもRAM設定から個別に試せます。 |
| 無圧縮テクスチャキャッシュ | MODの初期化以降にWaylithが書く新規・更新エントリを無圧縮にします。同じZIPで圧縮済みの既存エントリも読み込めます。OFFで元の設定に戻り、以降の書き込みに反映します。既存ZIPの形式変換や削除は行いません。 |
| JIT先行コンパイル | タイトル画面とポーズ中に、ゲーム本体と有効MODの管理メソッドを共有低優先度ワーカー最大2枠で最大8,000件準備します。空きRAM、フェーズ設定、フレームガードに従い、対象外・成功・失敗・処理時間を表示します。OFFで追加処理を停止し、生成されたコードはプロセス終了時に解放されます。 |
| XMLパッチキャッシュ | 再起動後に有効。ロード順、結合済みDefsのノード構造と由来、ロード済みパッチの内容と分岐、Config内XML、本体とアセンブリの識別子を照合します。対応する標準パッチで成功した場合だけ、適用後のXMLと由来情報を1ファイルに保存します。独自パッチ、競合するHarmonyフック、不一致、破損がある場合は通常ロードを使います。 |
| VRAM常駐強化 | Waylithが `OffloadUnderPressure` の場合、既存GPU先読みの上限をドライバー予算の75%まで引き上げます。最低空き容量に達した場合や予算が取得できない場合は追加アップロードを止め、エンジンの退避と復帰に任せます。 |
| グラフィック資源の事前構築 | タイトル画面とポーズ中に、標準の単一・多方向グラフィック、添付グラフィック、一部の建物用マテリアルを既存のゲームキャッシュへ準備します。GPU先読みと1フレームの処理時間を共有し、構築後も予算を再確認します。単一の処理は予算時間を超える場合があります。 |
| メッシュの異方性フィルタ | 初期値1×または2×の繰り返し・ミップ付きテクスチャに最大4×を適用します。対応Vulkanデバイスでのみ稼働し、Graphics Settings+やIsoRim系の設定を検出すると停止します。OFFで変更した値を復元し、描画が使用するサンプラーを更新します。 |

GCの比較では同じセーブ、ゲーム速度、画面、MOD構成を使い、通常起動またはWorkstationで基準を取った後にServerを試してください。ゲーム内の表示で適用された種類を確認できます。

```powershell
.\tools\Start-RimWorldGc.ps1 -GameExecutable "D:\Games\RimWorld\RimWorld.exe" -Profile Server -ServerHeapCount 8
```

`-ServerHeapCount` を省略するとランタイム既定のヒープ数を使用します。

2026-11-20 の実機計測（Windows 11、16 論理 CPU、218 MOD、1.7.5014 rev1195、速度 3）では、`DOTNET_gcServer=1` だけを付けて起動すると Server GC になり、GC の停止は 1.15% から 0.14%、最悪の 10 秒は 179 ms から 73 ms、ロード中の停止は 4.1 s から 1.3 s に減りました。GC のコミット量の増加は約 115 MiB でした（1 回ずつの比較。詳細は [PC での短い計測](docs/testing/pc-quick-measurement-ja.md)）。PowerShell を使わずに起動するときは、`tools/Start-RimWorld-ServerGc.cmd` をダブルクリックします（MOD が `RimWorld\Mods` にあるとき。ほかの場所なら `RimWorld.exe` をこのファイルにドラッグします。Windows ではまだ試していません）。[.NET GCの構成仕様](https://learn.microsoft.com/dotnet/core/runtime-config/garbage-collector)

## 実アセット積極活用プリセット

MOD設定の **実アセット積極活用プリセットを適用** でワーカー枠を論理CPU数−2に設定し、優先度の低いワーカーでファイル先読みとアセット検査を実行します。通常・高速プレイでは、同じ速度で計測したTPS・フレーム間隔P95を基準に、負荷が高まるとワーカー枠を抑えます。戦闘などで実効ゲーム速度が変わると基準を取り直します。RAMは実際の `Assets.zip` の共有ページに使い、常駐予算を少なくとも4 GiBに引き上げて、6 GiB以上の空きを残すよう監視します。GPU対応環境では、ドライバー予算の最大75%、最低空き2 GiBの範囲で実テクスチャを先読みします。

GPU先読みはエンジンがアトラス作成後に退避させた元画像を除外します。需要優先をONにすると、Waylithが記録した再読み込み履歴を使い、次回の先読み巡回でよく再読み込みされる画像を優先します。本MODのアップロードは順位から差し引きます。WOWGAGのJIT準備が有効な場合は、本MODのJIT準備を休止し、設定画面に理由を表示します。

### 起動前のパック先読みとGPU圧縮

対応ビルドでは、Waylithが選んだキャッシュ世代・エンコード方式・インストールID・MODルートのハッシュを照合してZIPを選びます。アセットパックはエンジンが実際に開いたパスを使います。**起動前の先読み用に使用中のアセットパック一覧を出力** をONにしてタイトル画面まで進むと、RimWorldのユーザーデータフォルダに `MoreUseResources-StartupPacks.json` が作成されます。次回起動時に渡すと、一覧とMOD構成・ファイル情報を照合し、予算内のファイルを先読みします。`-WarmPackBudgetMiB` と `-WarmTimeoutSeconds` で読み取り容量と作業時間の目安を指定できます。

```powershell
.\tools\Start-RimWorldGc.ps1 -GameExecutable "D:\Games\RimWorld\RimWorld.exe" -Profile Default -GpuTextureEncoding -StartupPackManifest "D:\RimWorldUserData\MoreUseResources-StartupPacks.json"
```

`-GpuTextureEncoding` はそのゲームプロセスの `WAYLITH_LOAD_ENCODE` を `gpu` に設定します。Waylithの条件を満たす画像のブロック圧縮が対象です。対応外の画像はエンジンの通常処理を使い、GPU方式のテクスチャキャッシュには別の名前が使われます。GPU方式で起動した後に作られた一覧を、次回のGPU方式起動で使うとそのキャッシュも先読みできます。

## ビルドと検証

.NET SDK 10.0.100、NuGet、Python 3を使用します。ゲーム用DLLはRimWorld 1.7.5011の参照パッケージでビルドします。ZIPにはMOD自身のDLL、設定データ、README、任意のGC起動スクリプトが入ります。

```sh
dotnet test Tests/MoreUseResources.Tests.csproj -c Release
dotnet build Source/Game/MoreUseResources.csproj -c Release
cp Source/Game/bin/Release/net10.0/MoreUseResources.dll Assemblies/
python3 tools/package_mod.py dist/Rimworld-MoreUseResources.zip
```

起動スクリプトの検証は一時ファイルだけを使い、ゲームを起動しません。

```sh
pwsh -NoProfile -File tools/Test-StartRimWorldGc.ps1
```

1.7.5014 rev1195 は本体DLLが手元にないため、参照パッケージ（Krafs.Rimworld.Ref 1.7.5014-unstable）で、このMODが呼ぶ・パッチする・リフレクションで読む型の宣言が5011と同じことと、ビルドが通ることを確かめました。メソッドの中身は比べていません。

Windows 1.7.5011 rev24の実DLLで、フレーム更新、セーブ、Waylithのテクスチャ再アップロードとVRAM予算取得、区画メッシュの変換と転送キュー、シェーダーキャッシュの読み取りの実装を静的に確認しました。他MOD併用時の確認内容と未確認事項は[静的検証の記録](docs/review/2026-11-17-external-mod-coexistence-ja.md)にあります。実ゲームでのMOD起動・設定画面の操作、セーブ／オートセーブ／再ロード、GPU実機での使用量とフレーム時間は別途確認が必要です。
